# 难度：超简单（trivial）

## 判据

- 一句话能说完这次改动，且能指出确切位置（文件 + 行号或符号名）。
- 不改变任何对外行为契约：改文案、改样式、调参数、补一行判断、修一个拼写。
- 不涉及新增文件、新增依赖、跨文件联动。

上面任何一条对不上，就往上一级升。定高了浪费用户的时间，定低了模型会顺手牵羊——两个方向都别硬凑。

## 提示词骨架

```text
目标：<一处精确改动>，位置 <文件路径:行号 或 符号名>。

约束：只改这一处；不要顺手重排格式、不要优化周边代码、不要改无关文件。如果 <目标位置的实际内容> 与描述不符，先告诉我，别按猜测改。

完成后：<一句话说明改动前后的差异，或「跑 <命令> 并贴出输出」>。

输出：只给改动的最小 diff。
```

## 裁剪说明

- 可以省掉：上下文、实现指引、分阶段、变量说明。
- 必须保留：目标（带确切位置）、约束（尤其「不要顺手」）、验证方式、输出格式。这四块是小改不变成大改的全部依靠。
- 兜底条款不用单开一块，并进「约束」一行即可。句式写成通用的那个：「如果 `<目标位置的实际内容>` 与描述不符，先告诉我，别按猜测改」——数值型改动填「实际值」，删改代码填「实际的写法」，改类名填「实际类名」。超简单级别不编 API，只可能改错位置，这一句正好挡住。
- 篇幅控制在 10 行以内。超了说明难度定错了，回去用 `level-2-simple.md`。

## 工作方式和范围：压成一行

`work-modes.md` 里的片段是按中等以上难度写的，这一级整段搬会直接撑爆篇幅。压成这样：

```text
工作方式：直接动手，不要先出计划。
```

指定目录时，范围就是「只改 `<路径>` 这一处」。全仓扫描的写法在这一级几乎用不到——改动位置都说不清的小改，本身就不该定成超简单。

## 常见坑

- 小改最容易翻车的地方是模型「顺便重排格式」，一个 3 行的 diff 变成 200 行。所以「只改这一处」必须写，而且要比任何正面要求更靠前。
- 不要给这一级配 few-shot 示例，也不要配「先出实施计划」。超简单的任务要计划，只是让用户多等一轮，什么都换不到。
- 「完成后」那一行别省。哪怕只是「说明改动前后差异」，也能让用户看出模型有没有改到点上。
