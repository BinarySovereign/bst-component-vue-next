# 难度：较复杂（complex）

## 判据

- 跨模块、跨包，或改动会碰到对外接口、数据结构、状态流转、公共 API。
- 存在两条以上可行路径，选错的代价大。
- 需要保证「外部行为不变」，或需要分批提交以便回退。

## 提示词骨架

```text
目标：<可判定的终态>；<明确说明哪些对外行为必须保持不变>。

背景：<为什么要做，不改会怎样>。

上下文：
- 技术栈与版本：<语言/框架/版本、包管理器>。
- 涉及范围：<包/模块/目录>。
- 现状：<当前实现的结构与数据流，关键文件与符号>。

约束：
- 不改动对外 API：<函数签名 / 导出清单 / 组件 props>。
- 保持既有测试全绿；测试如需调整，只允许改内部断言，不得放宽断言强度。
- 不新增依赖；不引入 <临时兼容层 / TODO / 双轨逻辑>。
- 只改动 <目录白名单> 内的文件。

工作方式（分两阶段，阶段一必须等我确认）：
阶段一：先出影响面清单——所有受影响的文件与符号、各自的调用方、预计的改动方式，以及你不确定的点。不要写代码。
阶段二：我确认后按 <批次划分> 实施，每批保持可编译、可测试通过；每批完成后跑一次验证。

完成定义：
- <测试命令> 全绿；<类型检查命令> 无错。
- <对外行为对比方式> 显示差异为空（或仅剩允许变化的部分）。
- 每批都贴出实际执行过的命令与输出。

输出：影响面清单 → 分批改动说明 → 每批的验证结果与遗留问题。

兜底：不确定的 API / 版本 / 路径先查源码或文档；对行为不确定的地方，先写一个最小验证用例跑一遍，不要凭推测下结论。
```

## 裁剪说明

- 这一级有两根柱子不能删：「先出影响面清单再动手」和「对外行为不变」。删掉任何一根，剩下的约束都挡不住静默的行为漂移。
- 用户选的是直接开始时，也保留「批次划分」。一次大改没有中间可回退的点，出问题只能整体推倒。
- 篇幅 45~70 行。再长就该拆成多轮提示词，而不是继续往里塞。

## 常见坑

- 静默的行为漂移是这一级最大的风险：模型为了让编译通过，会顺手调整语义。所以要求「对外行为 diff 为空」，并且**给出对比手段**——只说「保持行为不变」是没法验证的。
- 影响面清单如果只有文件名、没有符号，等于没写。模型仍然会漏掉调用方，因为没有强制它沿调用链走一遍。
- 阶段一如果被模型跳过去直接写代码，说明「不要写代码」还不够硬。补一句「阶段一结束时不要产生任何文件改动」。
