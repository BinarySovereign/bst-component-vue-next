# 难度定级与模板选择

第 0 步里用户要给难度，第 1 步里要用这个难度挑模板。这份文件解决两件事：怎么帮用户把难度定准，以及定完级之后怎么把「难度、任务类型、工作方式、扫描范围、外部工具」五样合成一份提示词。

## 一、五级判据

| 级别 | 判据（满足其一即可） | 典型例子 | 模板 |
| --- | --- | --- | --- |
| 超简单 | 一句话能描述 diff，且能指出确切位置；不改变任何对外行为 | 改一句文案、调一个间距、修一个拼写、把阈值从 500 改成 300 | `difficulty/level-1-trivial.md` |
| 简单 | 改动落在单文件内，或新增一个独立函数/小组件；方案明显 | 给一个工具函数补边界处理；加一个不依赖外部状态的小组件 | `difficulty/level-2-simple.md` |
| 中等 | 单模块内多文件联动，或新增一个要对齐既有模式的常规功能 | 新增一个列表组件并接上现有数据流；修一个有明确复现路径的 bug | `difficulty/level-3-medium.md` |
| 较复杂 | 跨模块/跨包，或会碰到对外接口、数据结构、状态流；有多条可行路径 | 重构一个模块的内部结构但保持 API 不变；把一个库从 A 迁到 B | `difficulty/level-4-complex.md` |
| 复杂 | 方案还没定，要先调研或设计；或跨多个子系统、需要长时间无人值守执行 | 定位一个说不清来源的性能退化；为整个包补一套测试；CI 批量修复 | `difficulty/level-5-very-complex.md` |

## 二、怎么帮用户定级

用户经常答不出「这算中等还是较复杂」，这时别让他硬选。做两件事：

1. **让他用一句话描述这次改动**：改哪里、改成什么、动了会连带影响什么。
2. 你按上面的判据定级，然后复述理由：「你说的这个要动 X 的对外签名、还要同步改 3 个调用方，我放较复杂。」

定级时就看三句：**改哪 → 改几个地方 → 会不会碰到别人依赖的东西**。「别人依赖的东西」指接口、导出、数据结构、配置格式——一旦碰到，就往上加一级。

用户坚持用低的级别也行：按他的选择写，但交付时提一句这个级别通常覆盖不到的风险（比如「复杂 × 直接开始」容易一次改太大、回不了头）。

用户弃权（「我不太懂，你看着定吧」「随便」）时，不要退回空着，也不要拿这个当理由反复追问。按两条自己判：

1. **改动面**：动一个文件还是多个文件；
2. **是否触碰对外契约**：接口、导出、数据结构、配置格式、别人依赖的行为。

两条都不碰 → 超简单到简单；只碰改动面 → 中等；碰到对外契约 → 较复杂起步。定完在交付的「前置说明 → 由我判定」里注明是你判的，并给出依据（「你说的这个改了 3 个文件但没动对外签名，我放中等」）——写明依据，用户才有机会反驳，否则他只能接受一个不知道从哪来的等级。

## 三、把五样拼起来

定完级之后按这个顺序拼：

1. **难度定骨架和流程**：取对应难度模板。篇幅、分不分阶段、要不要强制确认，全由它决定。
2. **任务类型定内容重点**：从 `templates.md` 里取该场景特有的要求（调试要贴报错原文、补测试要写「不得改源码迁就测试」、代码审查要写「可以什么都不报」……）。难度和场景对不上时，流程听难度，细节听场景。
3. **工作方式定「怎么干活」那几句**：从 `work-modes.md` 取现成片段贴进去。它和难度可能冲突，冲突时先说清代价，再按用户的选择走。
4. **扫描范围定上下文块**：全仓扫描就用「自行定位」的写法并给检索线索（符号名、文件模式）；指定目录就用白名单写法，同时限制「读」和「改」。
5. **外部工具定「能用什么、不能用什么」**：第 6 项答「是」就写「可用工具」块——工具名逐个列出、写明不调未列出的工具、查不到就说查不到；答「否」但任务容易诱发模型自己去联网时，补一段「只用仓库内已有手段」并告诉它去哪儿找依据（lock 文件、本地类型定义）。纯本地小改不用表态。

## 四、常见误判

| 误判 | 后果 | 怎么发现 |
| --- | --- | --- |
| 把「跨文件」当成「复杂」 | 写出一段流程繁重的提示词，用户多等好几轮确认 | 跨文件但方案唯一 → 中等；只有「方案不确定」才够复杂 |
| 把「我不熟」当成「任务复杂」 | 同上 | 用户的不熟悉靠实现指引（指到参照文件）解决，不靠升难度 |
| 把「改动小」当成「超简单」 | 漏掉连带影响 | 只要动了对外行为（哪怕一行），至少从简单起步 |
| 根因未知的 bug 直接判「复杂」 | 写出一段「先调研出规格、再照规格执行」的两阶段提示词，用户其实只想要一个小修复 | 改动面还留在单模块内、只是根因和复现路径没定 → 中等 + 计划模式；确认要跨模块改才升较复杂 |
| 忽略无人值守 | 模型遇到歧义自己决定，批量任务被污染 | 用户提到 CI / 批量 / 不用我盯着 → 至少较复杂，且必须写「跳过并记录」 |
| 难度定了但不落进成品 | 用户看不出你按哪一级写的，也没法纠错 | 交付时带上「前置说明 → 选型」那一行，写明难度与工作方式 |
