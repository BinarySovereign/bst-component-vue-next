# 主题定制

组件库的主题能力全部建立在**设计令牌**之上：颜色、字号、行高、圆角、尺寸阶梯都以 `:root` 上的 CSS 自定义属性表达，组件样式只引用令牌、不写死取值。因此换主题有两种手段，且都不需要改动组件源码。

## 令牌的分层

| 层次 | 内容 | 典型前缀 |
| --- | --- | --- |
| 原始色板 | 品牌 / 警告 / 错误 / 成功 / 中性 五组各 10 档 | `--bst-brand-color-*`、`--bst-gray-color-*` |
| 语义令牌 | 背景、文字、描边等按用途命名的取值，指向原始色板 | `--bst-bg-color-*`、`--bst-text-color-*`、`--bst-component-stroke` |
| 字体与尺寸 | 字号、行高、字体简写、尺寸阶梯、内外边距 | `--bst-font-*`、`--bst-size-*`、`--bst-comp-*` |
| 圆角与阴影 | 圆角阶梯与投影 | `--bst-radius-*`、`--bst-shadow-*` |

::: tip 优先使用语义令牌
`--bst-gray-color-3` 这类原始色板在明暗两套主题中的语义会反转（亮色下是浅灰描边，暗色下同一编号不再是描边色）。
需要描边就用 `--bst-component-stroke`，需要容器底色就用 `--bst-bg-color-container`，这样才能自动跟随主题。
:::

## 切换明暗

组件库通过 `:root` 上的属性或类名切换，两种写法都受支持：

```ts
// 写法一：属性开关
document.documentElement.setAttribute('theme-mode', 'dark');

// 写法二：类名开关
document.documentElement.classList.add('bst-theme-dark');
```

::: warning 与第三方暗色体系并存时需要桥接
多数站点框架（包括本文档站使用的 VitePress）切换暗色时只给 `<html>` 挂自己的类名，
与组件库的开关**不同名**。此时需要监听框架的主题状态并同步到 `theme-mode`，否则组件不会跟着变暗。
本文档站的桥接实现见 `.vitepress/theme/index.ts` 的 `setup()`。
:::

## 覆盖单个组件的取值

除全局令牌外，部分组件存在「组件专有量」——全局令牌无法表达、且需要被外部覆盖的取值，
组件样式会以组件自己的 CSS 变量声明，可直接在业务样式里覆写：

```css
/* 形式：在组件根类名上覆写该组件专有的 CSS 变量 */
.bst-<组件名> {
  --bst-<组件名>-<变量名>: <取值>;
}
```

取值的优先级为：组件 Props > CSS 变量覆盖 > 默认值。
各组件实际暴露的变量名、默认值与约束，以对应的组件文档页为准（组件落地后补全）。
